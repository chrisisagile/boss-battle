# Bug triage

Read the issue, relevant source, project Specs, and project Context before reaching a conclusion.

Return:

1. A concise problem statement.
2. Severity and user impact.
3. Evidence from the repository.
4. Likely owning area.
5. Reproduction or verification steps.
6. A recommended next action.

Do not change the issue until the workflow receives explicit approval.
