# Quickstart: QR Game Join

## Prerequisites

- `pnpm install`
- Docker available for the self-hosted Convex stack used by Aspire
- Playwright browsers installed once via `pnpm test:e2e:install` when running
  the browser smoke suite

## Run Locally

1. Start the full stack:

   ```bash
   pnpm dev
   ```

2. Open the host application from the Aspire-provided web URL.
3. Create a new session from the host landing screen.
4. Confirm the host display shows:
   - a QR code
   - the six-character join code
   - large-screen join instructions
   - a live joined-player roster

## Manual Verification

### Host Flow

1. From `/`, create a session.
2. Verify the app navigates to `/host/$joinCode`.
3. Confirm joining starts in the open state.
4. Close joining from the host route and confirm new join attempts are rejected
   without removing existing players.

### Player Flow

1. Scan the QR code or open `/join`.
2. Enter a valid join code manually if QR scanning is unavailable.
3. Submit a display name from `/join/$joinCode`.
4. Confirm the mobile route shows joined confirmation and waiting-state text
   when the player joined during an active participation window.
5. Attempt the same display name from another device and confirm duplicate-name
   rejection.

## Automated Verification

Run the narrowest useful checks first:

```bash
pnpm lint
pnpm test
pnpm test:e2e
```

Focused expectations after implementation:
- Vitest covers join-code helpers, display-name validation, and route state
  rendering
- AppHost smoke covers booting the full stack and loading the joinable host
  route through Aspire

## Notes

- `VITE_CONVEX_URL` is supplied by the Aspire AppHost during `pnpm dev`
- Convex schema and generated clients must be regenerated by tooling, not
  edited directly
